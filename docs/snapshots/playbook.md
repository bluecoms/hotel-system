호텔 운영시스템 UX 플레이북 (v1, 1p)
1) 공통 톤 & 용어

라벨 문체: 명사형/중립형. 예) “체크인 일자”, “예약 상태”, “저장”.

버튼 문구: 동사원형 한 글자 수축 금지. 예) “저장”, “예약 확정”, “환불 처리”.

오류 톤: 해결 행동 제시. 예) “객실 배정에 실패했습니다. 다시 시도하거나 다른 객실을 선택하세요.”

2) 레이아웃 패턴 (4종)

대시보드: 상단 KPI 카드(1행 3~4개) → 최근 예약/알림 → 작업바(자주 쓰는 액션).

보드리스트: 상단 FilterBar → 테이블(좌: 식별, 우: 상태/금액/시간) → 하단 페이지네이션.

디테일폼: 좌측 폼, 우측 요약/요금. 저장 버튼은 우상단 고정(스크롤 독립).

마스터관리: 좌측 목록, 우측 상세/폼—분할 레이아웃.

3) 네비게이션 & 액션

상단 우측 버튼: 기본 액션(저장/확정/발행). 파괴적 액션은 “더보기(⋯)” 안으로.

좌측 취소/뒤로, 우측 진행/저장 일관.

FAB/부유 버튼 금지(데스크톱 중심).

4) 테이블 규칙

정렬 기본: 시간·금액은 내림차순, 텍스트는 오름차순.

컬럼 폭: 식별(넓게) < 상태/태그(좁게). “메모/비고”는 말줄임표 처리.

행 인터랙션: 행 클릭 → 우측 패널 or 상세; 체크박스는 배치 작업용.

빈 상태: “조건을 조정해 검색해 보세요” + 바로가기(필터 초기화).

5) 필터/검색(필수)

필수 필터 3종: 기간, 상태, 채널(OTA/직영/전화).

기본 기간: 오늘 00:00–현재(운영 성격에 맞게 최근 7일 옵션 제공).

검색 입력: 한 칸(이름/전화/예약번호 통합 검색). 엔터=검색, ESC=초기화.

6) 폼 & 유효성

라벨 위치/정렬: 상단 좌측 정렬, 필수는 *대신 “(필수)” 텍스트.

에러 표기: 필드 하단 1줄 + 상단 토스트 1개(중복 경고 금지).

포커스 이동: 에러 첫 필드로 자동 스크롤 & 포커스.

저장 단축키: ⌘/Ctrl + S = 저장(가능하면 Debounce 500ms).

7) 한글 가독 규칙

기본 글꼴: --font-base(이미 적용). 본문 14–16px, 행간 1.5, 문단 간격 12px.

숫자/통화: 3자리 콤마, 통화기호 KRW 생략(페이지 상단에 통화 단위 표기), 소수점 0은 감춤.

날짜/시간: YYYY-MM-DD HH:mm(24h). 타임존 표기는 페이지 하단 푸터 1회만.

8) 상태·태그 컬러 체계(토큰 사용)

성공/완료: success

경고/주의: warning

오류/취소: error

정보: info

브랜드 강조: primary(골드)만 사용. CSS로 직접 색 지정 금지(테마 사용).

9) 접근성 & 키보드

포커스 순서: 좌→우, 상→하. 탭 순서 어긋나면 Bug.

터치 최소: 44×44px. 클릭 타깃 간격 최소 8px.

대비: 본문 텍스트 WCAG 4.5:1 이상(현재 토큰 기준 통과).

10) 로딩/에러/빈 상태

로딩: 스켈레톤(표/폼) 300ms 이상일 때만 표시.

에러: 한 화면 1개 토스트 + 필드 하단 구체 사유.

빈 상태: 아이콘 + 한 줄 설명 + 주 버튼 1개.

측정 & 운영
A/B 없이도 빠르게 확인하는 지표(주 1회)

NPS-lite(5문항): “예약 등록이 쉬웠나요?”(1–5), “에러 해결이 쉬웠나요?” 등.

과업 시간: “신규 예약 등록” 평균 ≤ 90초, “체크인 처리” ≤ 30초.

에러 복구 시간: 폼 에러 → 성공 저장까지 ≤ 10초.

QA 체크리스트(릴리스마다)

키보드로만 폼 저장 가능(Tab/Shift+Tab/Enter/ESC).

필수 누락 시 첫 에러 필드로 포커스.

테이블 정렬 초기값과 필터 초기 상태가 문서와 동일.

모바일 브레이크포인트서 터치 타깃 44px 유지.
