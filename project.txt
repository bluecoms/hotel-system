#  프로젝트 운영 가이드 (PM 배포용)

## 1. 업무 지시 체계

* **PM-Hub 세션(이 방)**:
  모든 업무 지시는 **여기서만 발행**.
* **지시 방식**:

  1. 기능명세(DoR: Definition of Ready) 1p 작성
  2. 담당 팀 지정 (BE-Core, FE-Core, QA-Release)
  3. 완료기준(DoD: Definition of Done) 명시

예시:

```
[지시] 페이즈1 - 대시보드 읽기전용
- 담당: FE-Core, BE-Core
- DoR: KPI 엔드포인트 명세서 참고
- DoD: 로그인→메뉴→대시보드 진입, mock 데이터라도 화면 렌더 성공
- 산출물: Feature Spec 1p, API 계약 1p, 테스트 카드 1p
```

---

## 2. 피드백 수집 프로세스

* **개별 세션 보고**:
  각 팀은 자기 세션에서 결과물(코드/문서)을 완성하면 PM-Hub에 **요약 보고**.
* **보고 형식(간단)**:

  ```
  [보고] FE-Core
  - 진행: http.ts 헤더처리 완료
  - 차주계획: Router meta 표준화
  - 리스크: axios 잔재 발견 → 제거 필요
  ```
* **PM 검토 후 승인/수정 요청**
  승인되면 QA-Release가 문서/테스트를 갱신.

---

## 3. 산출물 관리

* **종류 (모두 1p 형식)**

  1. Feature Spec (기능명세)
  2. API 계약서 (요청/응답 JSON 예시 포함)
  3. 테스트 카드 (curl/httpie 스크립트 + 기대값)
  4. 릴리즈 노트 (변경/마이그레이션/플래그/롤백)

* **위치**:
  `/docs/runbooks/features/{feature}/` 아래에 저장 (예: `/docs/runbooks/features/dashboard-kpi/feature_spec.md`)

* **QA 역할**:

  * 팀원 제출 산출물을 취합·정리·형식 맞춤
  * Git에 올려 **싱글소스 유지**
  * 테스트 카드 실행해 DoD 충족 확인

---

## 4. QA 책임 (품질 게이트)

QA는 **3가지 문지기 역할**을 가집니다:

1. **문서 게이트**: 모든 산출물이 1p 템플릿 맞는지 확인
2. **테스트 게이트**: 계약 테스트/릴리즈 체크리스트 실행
3. **릴리즈 게이트**: DoD 충족 여부 확인 후 PM에 보고

---

## 5. 전체 프로세스 흐름

```
PM 지시(DoR 발행)
   ↓
담당팀 개발/구현
   ↓
팀 보고(PM-Hub)
   ↓
PM 승인/수정요청
   ↓
QA 취합/정리
   ↓
QA 게이트 테스트
   ↓
릴리즈 (태깅/배포)
   ↓
운영 반영
```
