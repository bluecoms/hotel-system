✅ 기준정보로 추가 관리해야 할 항목들 (도메인별 제안)
 1. 운영(Operations) 기준정보
항목	설명	엔드포인트 예시
Facilities (부대업장)	식음(FNB), 사우나, 연회장, 주차 등 업장 목록	/api/master/facilities
Rooms (객실유형)	스탠다드/디럭스/스위트 등 객실 타입	/api/master/room-types
Closings (마감코드)	일마감 상태코드 OPEN/CLOSED/LOCKED 등	/api/master/closing-status
Housekeeping Codes	청소상태 코드 (CLEAN, DIRTY, OOO 등)	/api/master/hk-status

 이 4개는 “일마감 / 하우스키핑 / FNB / 시설관리”의 기준단위가 됩니다.
지금까지도 언급하셨던 “부대업장 파티션”도 여기 Facilities로 자연히 포함돼요.

 2. 회계/정산(Finance) 기준정보
항목	설명	엔드포인트 예시
Expense Categories (지출항목)	경비분류(식자재/전기/급여/소모품 등)	/api/master/expense-categories
Revenue Codes (매출코드)	객실/FNB/부대시설 등 매출 분류코드	/api/master/revenue-codes
Tax Codes (세금코드)	VAT 등 세금률 관리	/api/master/tax-codes

 나중에 재무리포트나 마감대시보드(KPI)와 직접 연동됩니다.
지금 expenses 업로드 테이블에도 이 분류들이 들어가야 완성돼요.

 3. 계약/인사(HR) 기준정보 확장
항목	설명	엔드포인트 예시
Positions (직위)	‘직책’보다 상위 개념, 예: 본부장, 팀장, 파트장	/api/master/positions
Employment Types (고용형태)	정규/계약/일용 등	/api/master/employment-types
Salary Policies (급여정책)	월급/시급/성과급 규정	/api/master/salary-policies

 이미 contracts.py와 연결 가능.
이 3개를 마스터화하면 직원 계약/급여 계산시 완전한 구조가 돼요.

 4. 판매(Sales/Channel) 기준정보
항목	설명	엔드포인트 예시
OTA Commissions (수수료율)	OTA별 기본 커미션율	/api/master/ota-commissions
Rate Plans (요금제)	숙박요금제, 조식 포함 등	/api/master/rate-plans
Promo Codes (프로모션 코드)	할인·패키지 코드	/api/master/promo-codes

 OTA 채널과 한 세트로 묶이게 됩니다.
특히 commission과 rate-plan은 이미 “업로드 → 정산” 파이프라인에 직결돼요.

 5. 기타 전역 마스터
항목	설명	엔드포인트 예시
Countries / Currencies	국가·통화 기준코드	/api/master/countries, /api/master/currencies
Languages	UI 및 고객언어 코드	/api/master/languages
Holidays	공휴일/특일 관리	/api/master/holidays

 공휴일은 “일마감 달력”에서 색상 강조 시 필요했던 항목이에요.

✅ 정리하면
분류	신규 마스터 후보	핵심 목적
운영	facilities / room-types / hk-status / closing-status	일마감·하우스키핑 기준
회계	expense-categories / revenue-codes / tax-codes	정산/회계 분류
인사	positions / employment-types / salary-policies	계약/급여 정책
판매	ota-commissions / rate-plans / promo-codes	OTA 연동 및 매출분석
공통	countries / currencies / languages / holidays	전역 기준정보

 추천 순서
1️⃣ OTA Commissions (지금 OTA와 바로 연결됨)
2️⃣ Facilities (부대업장)
3️⃣ Expense Categories (지출 내역 분류)
4️⃣ Holidays (공휴일 캘린더용)
